# راهنمای نصب

## قبل از اجرا

۱. سرور ایران اختصاصی یا سروری بدون listener روی 80/443 آماده کنید. `sudo ss -lntp` پورت‌های باز را نشان می‌دهد. نصب‌کننده وب‌سرور موجود را جابه‌جا نمی‌کند.

۲. `A panel-ir.hamrahgate.ir` را به IPv4 ایران تنظیم کنید. در Cloudflare ابر خاکستری (DNS only) باشد؛ دامنه تونل هم اگر استفاده می‌کنید باید DNS only باشد. برای این نسخه AAAA منتشر نکنید.

۳. از سرور خارج، IP ایران و پورت انتخابی باید قابل دسترس باشد. reverse tunnel از خارج به ایران شروع می‌شود؛ فیلتر بودن IP خارج برای مرورگر ایران لزوماً به معنای بسته بودن این مسیر نیست. قبل از خرید سرور، امکان اتصال همین دو سرور را بررسی کنید.

۴. در سرور خارج مشخص کنید پنل روی کدام endpoint محلی HTTP یا HTTPS است:

```bash
curl --connect-timeout 5 --max-time 10 -i http://127.0.0.1:8000/dashboard/
sudo ss -lntp
```

خروجی داشبورد باید HTTP 200 باشد. اگر Marzban داخل Docker است، endpoint باید از **host خارج** قابل دسترس باشد؛ `127.0.0.1` در این پروژه شبکه host است. برای HTTPS آدرس `https://127.0.0.1:PORT` و یکی از نام‌های DNS موجود در SAN گواهی را وارد کنید. پل TLS داخلی پروژه CA و hostname را بررسی می‌کند و از `-k` استفاده نمی‌کند.

۵. SSH را حفظ کنید و فایروال ارائه‌دهنده را جدا از فایروال سیستم بررسی کنید.

## نمونه UFW در ایران

اگر UFW از قبل فعال است، بعد از جایگزینی IP واقعی خارج:

```bash
sudo ufw allow 80/tcp
sudo ufw allow 443/tcp
sudo ufw allow from FOREIGN_PUBLIC_IP to any port 2333 proto tcp
sudo ufw status
```

`FOREIGN_PUBLIC_IP` مقدار نمونه است. برای پورت سفارشی، 2333 را عوض کنید. این راهنما UFW را خودکار enable/reset نمی‌کند. قبل از فعال‌سازی هر فایروال، پورت واقعی SSH را allow کنید. پورت 18000 فقط loopback است.

## ترتیب نصب

دستور README با `iran` روی ایران اجرا شود. بعد از دریافت pairing code، همان دستور با `foreign` روی خارج اجرا شود. نصب ایران پیش از نصب خارج طبیعی است؛ تا اتصال خارج، درخواست‌های پنل ممکن است timeout یا 502 شوند.

نصب خارج، HTTP محلی و اتصال TCP به ایران را پیش از راه‌اندازی بررسی می‌کند. رمز ورود پنل یا SSH از شما دریافت نمی‌شود. ورود نهایی از داشبورد اصلی Marzban انجام می‌شود.

## گواهی

Certbot گواهی دامنه جدید را با HTTP-01 می‌گیرد. برای چالش اولیه یک Nginx موقت روی پورت 80 اجرا می‌شود؛ Certbot از ابتدا webroot پروژه را برای صدور و تمدید ذخیره می‌کند. پورت 80 باید برای تمدید باز بماند. بعد از نصب دو طرف:

```bash
sudo panel-tunnel renew-test
systemctl list-timers --all | rg certbot
```

اگر `rg` ندارید، خروجی `systemctl list-timers --all` را بررسی کنید. بسته توزیع باید timer تمدید Certbot را داشته باشد. بعد از تمدید، deploy hook فقط Nginx پروژه را reload می‌کند. فایل‌های تمدید سایر دامنه‌ها تغییر نمی‌کنند. برای دامنه‌ای که قبلاً در Certbot مدیریت می‌شد از این پروژه استفاده نکنید؛ یک دامنه تازه و اختصاصی انتخاب کنید.

## بعد از نصب

`doctor` را روی هر دو سرور اجرا و دامنه را از اینترنت داخل ایران باز کنید. نصب روی سرورهای واقعی، گرفتن گواهی عمومی و تست مسیر ایران باید روی همان سرورها انجام شود؛ تست‌های پروژه این موارد را شبیه‌سازی کامل نمی‌کنند.

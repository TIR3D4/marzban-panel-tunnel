# عیب‌یابی و بازیابی

## دستورهای اول

```bash
sudo panel-tunnel doctor
sudo panel-tunnel status
sudo panel-tunnel logs
```

در ایران:

```bash
sudo tail -n 50 /var/log/marzban-panel-tunnel/nginx-error.log
```

قبل از ارسال لاگ برای دیگران، اطلاعات شخصی را بررسی کنید؛ فایل settings و pairing code را ارسال نکنید.

## مشکل و اقدام

| نشانه | بررسی |
|---|---|
| نصب ایران: port unavailable | listener با `sudo ss -lntp`؛ پروژه روی پورت وب‌سرور فعلی نصب نمی‌شود |
| دریافت گواهی شکست می‌خورد | DNS A، نبود AAAA اشتباه، DNS only، TCP/80 و فایروال ارائه‌دهنده |
| curl محلی خارج پاسخ نمی‌دهد | پورت HTTP مرزبان، Docker host binding و فعال بودن TLS |
| گواهی HTTPS محلی رد می‌شود | مقدار `upstream_tls_name` باید دقیقاً یکی از نام‌های SAN گواهی مرزبان باشد؛ زنجیره گواهی نیز باید معتبر باشد |
| سرویس TLS bridge خطا دارد | `sudo panel-tunnel logs` و دسترسی محلی به پورت HTTPS مرزبان را بررسی کنید |
| خارج به ایران وصل نمی‌شود | مسیر خروجی خارج، listener ایران، پورت و whitelist IP در فایروال |
| لاگ Noise/authentication خطا دارد | pairing code از همین نصب ایران و کلید/token بدون تغییر باشد |
| ایران 502/timeout می‌دهد | client خارج روشن باشد؛ upstream خارج HTTP 200 بدهد |
| doctor ایران موفق، مرورگر باز نمی‌شود | DNS/443/گواهی و دسترسی واقعی کاربر ایران؛ مسیر اینترنتی جداست |
| داشبورد می‌آید ولی ورود خطا دارد | درخواست `/api/admin/token` در Network مرورگر و پاسخ backend را بررسی کنید |
| redirect به دامنه اصلی رخ می‌دهد | تنظیمات redirect/host در backend؛ باید endpoint محلی مناسب برای دامنه دوم فراهم شود |
| تمدید گواهی خطا دارد | `sudo panel-tunnel renew-test`، TCP/80، gateway و timer Certbot |
| نصب روی ARM یا OS قدیمی متوقف می‌شود | نسخه 1.0 فقط x86_64 و Debian 12+/Ubuntu 22.04+ را پشتیبانی می‌کند |

## ادامه بعد از خطا

اگر تنظیمات ذخیره شده باشد، نسخه نصب‌کننده را دوباره دانلود و اجرا کنید:

```bash
bash /root/marzban-panel-tunnel-install.sh --resume
```

کلیدها دوباره ساخته نمی‌شوند. اگر شکست قبل از ذخیره state بوده، نصب عادی را دوباره اجرا کنید. نصب تراکنش کامل سیستم‌عامل نیست: بسته‌ها، user یا باینری دانلودشده ممکن است بعد از خطا باقی بمانند. state و مراحل قابل resume برای بازیابی نگه داشته می‌شوند.

اگر نصب اولیه هنگام گرفتن گواهی شکست خورده، ابتدا DNS/firewall را درست کنید. اگر باینری با glibc سیستم سازگار نباشد، نصب متوقف می‌شود؛ OS پشتیبانی‌شده با بسته‌های به‌روز لازم است.

## حذف

```bash
sudo panel-tunnel uninstall
```

با تایپ `REMOVE` فقط سرویس‌های پروژه و command حذف می‌شوند. تنظیمات، باینری، packageها، کاربر سرویس و گواهی‌ها برای بازیابی باقی می‌مانند. نصب‌کننده با `--resume` قابل بازیابی است. حذف کامل فایل‌ها یا پاک‌کردن گواهی را پس از تهیه backup و بررسی نیاز سرور انجام دهید. پس از کنارگذاشتن دامنه، گواهی بلااستفاده آن را با `certbot delete --cert-name DOMAIN` حذف کنید؛ تمدید webroot بدون gateway کار نمی‌کند.

## محدودیت تست

تست integration پروژه انتقال واقعی HTTP در Noise و رد کلید server اشتباه را بررسی می‌کند. نصب apt، صدور گواهی عمومی، تمدید Certbot، راه‌اندازی systemd و دسترسی از اپراتورهای ایران باید روی سرور واقعی بررسی شوند.
